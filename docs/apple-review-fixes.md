## 2. Background audio fix (Guideline 2.5.4)

Root cause: the **expo-video config plugin** adds `audio` to `UIBackgroundModes` whenever `supportsBackgroundPlayback` **or** `supportsPictureInPicture` is enabled. Both were enabled in `app.json`.

Changes (mobile repo):
- `app.json` — expo-video plugin: `supportsBackgroundPlayback: false` (PiP flag kept `true` so **Android** PiP keeps working — Android PiP does not use `UIBackgroundModes`).
- `plugins/withRemoveBackgroundAudio.js` — **new** config plugin that strips `audio` from `UIBackgroundModes` (and deletes the key when empty). Info.plist mods run in *reverse* plugin-array order, so it is listed **before** `expo-video` in `app.json` to execute last. This guarantees no plugin re-adds the value at prebuild/EAS build time.
- `src/components/workout/ReelsVideoPlayer.tsx` — `staysActiveInBackground = false`, `showNowPlayingNotification = false` (video now pauses when app is backgrounded; no lock-screen media controls). In-app (foreground) audio/video is unchanged.

Consequence: iOS Picture-in-Picture for workout reels no longer works (iOS PiP requires the audio background mode). PiP calls are try/catch-wrapped and degrade silently. Android PiP is unaffected.

Verification (`npx expo config --type introspect`):
- `UIBackgroundModes` — **0 occurrences** in the resolved config (key fully removed).
- `expo prebuild -p ios` cannot run on Windows; EAS Build (macOS) generates Info.plist from exactly this resolved config. Optionally verify the final `.ipa` after the build: `unzip -p app.ipa 'Payload/*.app/Info.plist' | plutil -p -` should show no `UIBackgroundModes`.

⚠️ The `.com` account's subscription **expires 2026-07-13** (2 days!). Expired subscriptions lock Home-screen features. The seed script extends it to 90 days ACTIVE.

Credentials are **not** hardcoded anywhere in the mobile app (verified by grep).

## 4. Seed script (backend repo `DietTemple`)

New file: `src/scripts/seedAppleReviewAccount.ts`, npm script **`seed:apple-review`**.

Idempotent (safe to re-run): users upserted by email, plan/nutrition/history upserted by natural keys, favorites checked before insert. It never deletes or touches other users' data.

Run on the production server:
```bash
cd <backend>
npm run seed:apple-review
# optional overrides:
# APPLE_REVIEW_EMAILS=user1@diettemple.tn APPLE_REVIEW_PASSWORD=... APPLE_REVIEW_SUBSCRIPTION_DAYS=120 npm run seed:apple-review
```

Note: `seedUser1Plan`, `seedUser1Nutrition`, `seedExerciseHistory` were parametrized with an optional `userEmail` argument (default unchanged, existing npm scripts unaffected).

**Not executed locally** — no MongoDB on this machine; script is type-checked (`tsc` clean) but must be run on the server, then verified with the login `curl` above.

## 7. iPad compatibility

Finding: resolved config allowed **all four orientations + Split View** on iPad (`UIRequiresFullScreen: false`) while the app is designed portrait-only and 30+ files capture `Dimensions.get('window')` at module scope (stale on rotation/resize → broken layouts).

Fix (`app.json` → `ios`): `requireFullScreen: true` + `UISupportedInterfaceOrientations~ipad` limited to portrait/portrait-upside-down. This is App Store-legal (portrait-only apps must opt out of multitasking) and eliminates the rotation/Split View layout-breakage class. Verified in resolved config. No screens were redesigned.

Note for a future release: migrate module-scope `Dimensions.get('window')` to `useWindowDimensions()` if landscape/multitasking support is ever wanted.

## 8. Account deletion (Guideline 5.1.1(v))

The in-app "signup" funnel only submits a lead (`POST /api/leads`, verified live); accounts are provisioned by the gym. Deletion implemented anyway (users do sign in):

Backend (`DietTemple` repo):
- **`DELETE /api/me/account`** (new, in `src/routes/me.routes.ts`) — authenticated, requires the current **password** in the body, admin accounts refused.
- `src/services/accountDeletion.service.ts` (new) — deletes the user + personal data across 18 collections (subscription, programs, nutrition logs, workout/exercise history, favorites, cart, check-ins, progress photos, coach notes/events) and the locally stored avatar. **Orders are retained** for financial record-keeping. Because the auth middleware re-loads the user on every request, deleting the user invalidates all outstanding JWTs (session invalidation).

Mobile:
- `src/screens/DeleteAccountScreen.tsx` (new) — consequences list, password confirmation, destructive `Alert` confirm, success/failure feedback, clears local storage, resets to Login.
- Entry point: **Profil → COMPTE → Supprimer le compte** (`ProfileScreen.tsx`), route registered in `App.tsx` + `RootStackParamList`.

⚠️ Endpoint returns 404 on production until the backend is **redeployed** (verified). Deploy the backend before submitting.
